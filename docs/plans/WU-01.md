# WU-01 — Workspace scaffold: plan

**Status:** approved (2026-10-26) · **Depends on:** — · **Author:** main agent (Opus), 2026-10-26

## 1. Goal & scope

**Goal** (from `docs/work-breakdown.md`): an empty monorepo that installs, typechecks and lints on Windows and POSIX.

**In scope**
- `pnpm-workspace.yaml`, root `package.json` (`engines`, `packageManager`), `.nvmrc`
- `tsconfig.base.json` (CLAUDE.md §3 strict settings) and a `tsconfig.json` per package
- Empty packages, each with the right name and `"type": "module"`: `apps/web-nextjs`, `backends/api-nextjs`, `packages/domain-schema`, `tests/contract`, `journeys`
- `backends/api-fastapi` and `backends/api-go`: README and `.gitkeep` only
- ESLint flat config and Prettier at the root, including the `no-restricted-imports` rule that blocks `@vp/domain-schema/rules` in `apps/`
- `.gitattributes`, `.gitignore`, `.env.example`, `.editorconfig`, a README stub

**Out of scope:** Next.js app code and the `next` dependency (WU-06 and WU-12), Vitest, Playwright, Pact, lefthook and commitlint (WU-02), `zod` and the `exports` map contents (WU-04), and `gen`/drift scripts (WU-04).

## 2. Approach & key decisions

| # | Decision | Why / CLAUDE.md | Rejected alternative |
|---|---|---|---|
| D1 | **Pin TypeScript `6.0.3`, not `7.0.2` (`latest`).** | TS 7 is the native Go compiler. `typescript-eslint@8.72.1` declares the peer `typescript >=4.8.4 <6.1.0` because it needs the JS compiler API. Typed lint rules (§3, §9) need that API. We revisit once typescript-eslint supports TS 7. | TS 7 for `tsc` plus a second TS 6 for ESLint: two compilers that can disagree. |
| D2 | **Node `24.22.1` (Active LTS "Krypton") in `.nvmrc`**; `engines.node: ">=24.11.0 <25"`; `engineStrict`. | §3 "current LTS, pinned". Node 26 is still `lts: false` as of 2026-10-21. | Node 26 (not LTS yet). |
| D3 | **`packageManager: "pnpm@12.15.0"`** plus pnpm settings in `pnpm-workspace.yaml` (`saveExact: true`, `engineStrict: true`). | §3 pnpm only, exact pins. pnpm ≥10 reads its settings from the workspace YAML, so no `.npmrc` is needed. | `.npmrc`. |
| D4 | **pnpm `catalog:` for shared dev tool versions** (`typescript`, `@types/node`), exact versions. Later WUs add `zod`, `vitest` and others to the same catalog. | Gives one definition per version, so "exactly one `zod`" (§3) holds by construction as packages are added. | Repeating the version in each `package.json`, which drifts. |
| D5 | **Per-package `typecheck` = `tsc --noEmit`; root runs `pnpm -r typecheck`.** Each package lists `typescript` as its own devDependency (`catalog:`). | §3 strict `node_modules`: no reliance on hoisted bins. Packages stay independently checkable, which matters once Next.js has its own tsconfig needs. | `tsc -b` with project references: needs `composite` plus declaration emit, which is awkward with `noEmit` and with Next.js. |
| D6 | **`tsconfig.base.json`**: `strict`, `noUncheckedIndexedAccess`, `module: "ESNext"`, `moduleResolution: "bundler"`, `target: "ES2023"`, `verbatimModuleSyntax`, `isolatedModules`, `noEmit`, `skipLibCheck`, `noImplicitOverride`, `noFallthroughCasesInSwitch`, `forceConsistentCasingInFileNames`, `resolveJsonModule`. `types` is set explicitly per package, because TS 6 defaults `types` to `[]`. | §3. `verbatimModuleSyntax` makes the `import type` preference in §4.2 enforceable. | `exactOptionalPropertyTypes`: friction with Zod-inferred optional fields; can be revisited in WU-04. |
| D7 | **Each package gets a placeholder `src/index.ts` (`export {};`).** | `tsc` fails with "No inputs were found" on an empty `include`. | Leaving `src/` empty with a `.gitkeep`, which breaks typecheck. |
| D8 | **`domain-schema` gets its `exports` map now**, pointing at placeholder `src/wire/index.ts` and `src/rules/index.ts`. | §4.2. The lint-boundary check needs a real `@vp/domain-schema/rules` subpath to be meaningful. WU-04 fills in the contents. | Deferring the map to WU-04 means the DoD lint probe would test a specifier that doesn't exist. |
| D9 | **ESLint 10 flat config `eslint.config.js`**: `@eslint/js` recommended + `typescript-eslint` `recommendedTypeChecked` with `projectService`, then `eslint-config-prettier` last. JS config files use `disableTypeChecked`. | §3. Typed rules catch unsafe `any` from LLM output later (§7 "LLM output is untrusted"). | `strictTypeChecked`: a lot of noise on an empty repo; can be tightened in WU-02. |
| D10 | **Boundary rules**, with `no-restricted-imports` scoped by `files`: **(a)** `apps/**`: ban `@vp/domain-schema/rules` (and `/rules/*`), `@vp/api-*`, and any relative path into `backends/`; **(b)** `apps/**`: `@typescript-eslint/consistent-type-imports`; **(c)** `journeys/**`: ban `@vp/*` and relative paths into `apps/`, `backends/`, `packages/`. | (a) is the DoD. The `backends` ban and (c) come from §9 "no importing backend code into apps/" and §6.6 "journeys must not import". Each is one config entry, so it's cheapest to add now. | Only (a); then (c) would land in WU-15 after code exists that might already violate it. |
| D11 | **A durable boundary probe**: `scripts/lint-boundary-probe.mjs` uses the ESLint Node API (`lintText` with a virtual `filePath` under `apps/` and `journeys/`, type-aware parsing switched off for the probe) and asserts that each forbidden import produces an error and an allowed import (`@vp/domain-schema/wire`) does not. `pnpm lint` = `eslint . && node scripts/lint-boundary-probe.mjs`. | DoD "a deliberate import … fails lint", proven on every run rather than once by hand. A plain node script keeps it working on Windows and POSIX (§3). WU-02 may move it into Vitest. | A manual check with a temp file: proves it once, then rots. |
| D12 | **Prettier 3** at the root: `.prettierrc.json` (`singleQuote`, `trailingComma: "all"`, `printWidth: 100`), `.prettierignore` covering `generated/`, `contracts/pacts/`, `.llm-cassettes/`, `pnpm-lock.yaml`. Scripts `format` / `format:check`. | §2 marks those paths generated. Wiring `format:check` into a gate is WU-02 (lint-staged). | — |
| D13 | **Workspace globs list `backends/api-nextjs` explicitly**, not `backends/*`. | `api-fastapi` and `api-go` are not pnpm packages and never will be. | `backends/*` relies on pnpm skipping directories that have no `package.json`. |
| D14 | **One root `.env.example`** that documents every variable from CLAUDE.md §5, §6.5, §8.1 and §8.3, grouped by consumer (web, api-nextjs, tests). | §9 "kept current". Splitting it per app can happen in WU-06/WU-12, once each app actually loads env. | Per-app files now, for apps that don't exist yet. |

Package names: `@vp/web-nextjs`, `@vp/api-nextjs`, `@vp/domain-schema`, `@vp/contract-tests`, `@vp/journeys`. All are `"private": true` at version `0.0.0`.

**Pinned versions** (all exact): `typescript 6.0.3`, `@types/node 24.19.2`, `eslint 10.13.0`, `@eslint/js 10.0.1`, `typescript-eslint 8.72.1`, `eslint-config-prettier 10.1.8`, `globals 17.13.0`, `prettier 3.9.10`. `rimraf` and `cross-env` are not added yet because no WU-01 script needs them (WU-02 adds them when a script does).

## 6. Risks & open questions

1. **TS 6 vs TS 7 (D1).** `latest` is 7.0.2. Pinning 6.0.3 is a deliberate step back for typed linting. **OK to pin 6.0.3?**
2. **Scope extension (D10c, D11).** Adding the journeys import ban and the boundary-probe script goes slightly beyond the listed scope, but both are cheap and directly back CLAUDE.md §6.6 and §9. Say if you'd rather keep WU-01 minimal.
3. **`exports` map now (D8)** instead of in WU-04. WU-04 still owns the contents.
4. When Next.js arrives (WU-06/WU-12), `eslint-config-next` and Next's tsconfig requirements (`jsx`, `plugins`) will extend the per-app configs. The base config is chosen not to conflict (`moduleResolution: bundler`, `isolatedModules`).
5. pnpm 12 may enforce a `minimumReleaseAge` supply-chain delay. All the versions above are older than the default window, so this should not bite.

## 8. Deviations during implementation

- **Prettier ignores `*.md` and `.claude/`.** `format:check` flagged the pre-existing governance docs (CLAUDE.md, work breakdown, this plan), but only for markdown table padding, along with harness-owned `.claude/` config. Excluding them avoids churn and keeps hand-edited tables compact. Code, JSON and YAML are still formatted.
- **`.env.example` includes `ANTHROPIC_API_KEY=` (empty)**, which LLM_MODE `live`/`record` needs (§8.3).
- The boundary rule sets are exported from `eslint.config.js` (`appsRestrictedImports`, `journeysRestrictedImports`), so the boundaries are defined in one place.
